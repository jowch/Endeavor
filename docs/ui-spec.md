# Endeavor UI spec — main interface

Handoff for implementing the redesigned chat + notebook interface.

- **Target states (source of truth for look):** https://claude.ai/artifact/Y4NunVg55n9zNtL2oz7bUV — nine 1440×900 boards. Read exact values from the boards' `.dc.html` sources; do not port the markup.
- **Exploration history (why decisions were made):** https://claude.ai/artifact/Ws1rn2Dyuo9Q2cqQBZD2VA
- Both canvases are private until shared from their Share menu.

## Principles

1. **You co-author the notebook.** Hands-on users and delegate-everything users both feel at home; the notebook invites direct editing.
2. **Visual weight follows urgency.**
   | Tier | What | Treatment |
   |---|---|---|
   | Needs you now | Run / plan approvals | The only heavy element: orange edge + soft ring, filled orange primary |
   | Look when you like | Agent-edited, unrun cells | Orange status bar only — no badges, no header text |
   | Where you read | Chat messages | Brightest text, 14px |
   | Ambient | Sidebar, composer, controls | Smaller, grey, no emphasis |
3. **Native by default, CSS where needed, a thin adapter for the rest.** Every line injected into the notebook is maintained twice (Pluto, later Ember).
4. **Agent-agnostic.** Every "Claude" label comes from the ACP agent's name.

**Type** — Geist (UI), Geist Mono (cell names, paths, counts). Sizes: chat 14px/1.6; tool lines 13px; sidebar 12.5px; section heads 11.5px; toolbar 12px. The notebook keeps Pluto's own fonts (Vollkorn, Alegreya Sans, JuliaMono).

**Space** — 16px inset from every column edge (headers, transcript, composer, sidebar rows); 10px inside cards; 8px between related items, 16px between blocks. Column headers 44px.

**Radius** — cards, composer, bubbles 8px; buttons, menus 4–5px; chips, inline code 3px; gutter bars 2px; circles stay round. *(Open: Pluto's 4px everywhere in the chat panel.)*

## Motion

Quiet motion only: short fades and small slides for what appears, no springs, bounce or staggered lists. Tokens in `src/theme.rs`, helpers in `src/motion.rs`.

| Token | Value | Use |
|---|---|---|
| `motion_fast` | 120 ms | Something appearing; a line whose words change |
| `motion_standard` | 160 ms | The transcript easing to its end as content arrives |
| `motion_rise` | 4 px | How far an appearing thing moves into place |
| `motion_pulse` | 1.4 s | One breath of a working sidebar bullet, repeating |
| `ease_out` | cubic | Everything above |

- **Transcript.** While it follows its end, a growing reply or a new entry no longer jumps the view: the content lands below and the view eases to the new end, starting again from where it is when more arrives. Scrolled up, nothing moves. A live entry (a reply starting, a tool row, the changed-cells card) fades in; replayed history shows at once. A step line's words ("Read 3 cells", "Edited a cell, ran 2 commands, 1 denied") crossfade as calls arrive; while a run is folded and live, its latest call crossfades over the one before; the run's header fades in when a second call joins the first. Opening a step's details fades them in; closing is at once.
- **Above the composer.** The pinned plan, the waiting lines, the sign-in card and the approval card fade in and rise from the composer. Queued rows, the queue's heading and a removed row's Undo line do the same.
- **Menus.** The ⋮ / session menus, the sidebar's filter menu, the toolbar's menus and the new-session chips' menus fade in, moving 4 px from their button. Menus over the notebook show at once: their hole in the web view can't fade with them.
- **Not animated.** Exits (a closing menu or card goes at once: GPUI can't make a leaving element let clicks through, so a fading menu could take a second click), the confirm dialog and Settings (the web view's dimming is instant, so a fading scrim would not match it), tooltips, the sidebar (except a working row's pulsing bullet), the notebook pane's states, the find bar and the page's own overlays.
- **Never in the way.** Nothing delays input: what appears takes clicks and keys from its first frame, and focus moves at once. Nothing animates in the first frame after launch or in the frame that shows another session.
- **Reduce motion** (macOS's Accessibility setting, read at launch and on its change notification; GTK's `gtk-enable-animations` on Linux; Windows not yet) makes every duration zero, and GPUI stills the orbit. A working sidebar bullet then stays filled instead of pulsing.
- **Checking it.** In a debug build, `ENDEAVOR_MOTION_SCALE=10` plays every animation ten times slower; `0` turns motion off.

## Layout

- Three columns: sidebar · chat · notebook. **All resizable** by dragging dividers; sidebar within min/max and collapsible (⌘B). No full-width toolbar and no "focus" mode — full-width notebook comes from collapsing panes.
- **Per-column 44px headers**, dividers aligned: sidebar = traffic lights + sidebar toggle; chat = session title ⌄ (session menu: the sidebar row's ⋮ items for the open session; its Rename edits the title in place) + folder tag; notebook = filename. No horizontal rules; content fades out under the headers (below). When the sidebar is collapsed, traffic lights + toggle move to the start of the chat header.
- **The sidebar's past sessions show at launch**, from Endeavor's own record of its sessions, without waiting for Julia or Claude. Claude starts at launch alongside Julia; its listing then updates titles and times and drops sessions deleted elsewhere. Sessions Endeavor didn't make (such as the Claude Code CLI's) aren't listed.
- **Opening a past session** (boards POpen, POpenStates): the row opens on click. Until its history has loaded, the chat shows what Endeavor's record knows, centred on the same line as the notebook pane's starting block: the title, "Last active yesterday at 16:40 · fit_decay.jl" (and the server, for a server's session), and one muted line on what it waits for ("The conversation shows once Julia is running.", "… once Claude is running.", "The conversation is kept on lab-server, so it shows once Endeavor can reach it.", "The conversation appears once all of it has loaded."). One wait line above the composer names what is still on its way, with the time so far after 5 s: "Starting Julia… 0:12" (or "Connecting to lab-server…"), then "Loading the conversation…". The history then shows whole, scrolled to the end, not growing as it arrives, followed by a faint divider "Reopened today at 9:14". A session Endeavor has its own copy of (board TCopy) shows that copy at once instead of the summary, scrolled to the end, with a lock and "Read-only" after the folder tag and a faint "Loading…" as its wait line (or the line above, while Julia, the server or Claude is still on its way). When Claude's replay has all arrived it replaces the copy, matched by order and text, and the view keeps its place: if everything matches nothing moves; if the replay only adds messages at the end (the session was continued outside Endeavor), the view stays put, even at the end, and the floating button reads "N new messages ↓"; if earlier messages differ (compacted or rewound outside Endeavor), the thread changes around the view's top message, a muted note "Earlier messages were replaced (compacted, or rewound outside Endeavor)" marks where the two part, and the button reads "Jump to latest ↓". The divider follows the history as usual (a reopen with no turn since moves the last one instead of adding another). The composer stays usable ("Write a message. It sends once the session is open."); messages wait and go once it is, and there's no Stop while it loads. The notebook Endeavor recorded for the session opens as soon as the host's Julia is ready, without waiting for the history, in safe preview as any reopened notebook (shared if another session has it open; "Can't find" if its file is gone). Only a session with no recorded notebook waits for its history and opens the notebook Claude last opened there. The recorded notebook wins over the history's, so a file found with Locate file… stays found.
- **Fades, not blur** (canvas, LFade): GPUI can't blur what's behind an element, and the web view draws over native views. So the chat has gradient fades only: about 20 px from the page colour under the chat header and about 24 px into the page colour above the message box, each shown only when content sits under that edge. The notebook page fades out in a fixed 16 px gradient at its top edge (`frontend/src/theme.ts`, using Pluto's `--main-bg-color`, so it is right in both looks), and the sidebar's session list gets a 20 px fade under its "Sessions" heading when it scrolls. No fade takes mouse input.

## Chat

- **Transcript is top-anchored**: messages start at the top and fill down; stick-to-bottom only once it overflows, and only while the user is at the bottom.
- **Jump to latest**: once the user scrolls up from the end of a transcript that overflows (such as while Claude streams), a floating pill, "Jump to latest ↓", sits centred just above the composer area. A click scrolls to the end and follows again; scrolling back to the end does the same and the pill goes. After a replay that left the view in place it reads "N new messages ↓" (or "Jump to latest ↓") until the user goes to the end.
- **Endeavor's copy of the transcript**: each session's transcript is also saved, display-only, in Endeavor's support folder (`transcripts/<session id>.json`) when a turn ends and when the session closes; deleting the session deletes it, archiving keeps it, and a session its agent no longer lists loses it with its record. Kept: messages and their chips (pictures over ~150 KB left out), tool rows with their input and output cut to 4,000 characters per string and 100 items per list, thoughts, plans, notes, changed-cells cards and dividers; not kept: prompts, run-state notes and failure cards. It is never sent to the agent.
- **User message**: right-aligned bubble, `bg.raised`, 8px radius, max ~300px.
- **Tool calls**: collapsed by default, one line each — grey verb, light mono cell name, ± counts, `›` to expand (expanded shows the diff).
- **End of turn**: a card listing cells changed this turn (cell icon, name, `new` tag, ±, `›`); a row click scrolls the notebook to the cell and outlines it. Each cell is one row with its net ± over the turn; a deleted cell gets a `deleted` tag and no `›`; a cell left as it was, or added and deleted again, isn't listed; no card when no cell changed. Under the message: copy, pin, relative time.
- **Mid-turn**: working indicator (the orbit, an orange dot circling a tilted ring, + "Adding `residuals` · 12s"). The agent's plan checklist (✓ done struck through, ◐ current bright, ○ upcoming grey; "Progress · 1 of 3", collapsible) is **pinned above the composer** while the turn runs, then folds back into the transcript.
- **Approval card** (above composer; boards PAsk, PAskRuns, PAskManual, PAskKeys, PAskQueue): one card per session, the only heavy element (accent edge, soft ring, filled primary). A question in the verb of what it asks, names in mono: "Run `rates`?", "Edit `data` and run it?", "Add `residuals` and run it?", "Delete `old_fit`?", "Run 3 cells?" (names on a line under it, up to five, then "and N more"), "Run a command on lab-server?", "Let this notebook run?"; for the agent's own prompts (Manual, or a call its rules ask about) "Run a command on This Mac?", "Edit `notes.md`?", "Create `scripts/clean.jl`?" ("Replace …" over an existing file), "Fetch a web page?", "Edit `rates`?" for a notebook edit that doesn't run. Claude Code's own option labels and raw tool names never show.
  - Body: the code it runs, the change as a diff (removed lines first, in the transcript's diff colours), a new cell's code, a deleted cell's code struck through, or the command and the folder it runs in (the agent's description of the command between them). Up to 8 lines, then "Show all N lines ›", which opens the rest in place in a scroll area up to 40% of the window's height ("Show the first 8 lines ⌄" closes it). One muted line on what else happens: "Also runs N cells it needs that haven't run yet." (cells it depends on that never ran, as after leaving safe preview without a run), "Also re-runs N cells that depend on it.", "Nothing depends on it yet." (faint), "⌘Z in the notebook brings the cell back.", "Nothing runs. In Manual, every change to the notebook asks." (just "Nothing runs." in other modes), "Claude reads the page. Nothing on This Mac changes.", "New file in ~/…. Nothing runs." Before the runtime says what a run runs, the code box shows "…" and "Finding out what it runs…".
  - When the asked-about cell is off screen in the notebook (the page reports it), a first line names it with **Show in notebook →**, which scrolls the pane to it and outlines it for a second.
  - Buttons: **Deny** (esc) on the left, plain; on the right **Always this session** (⌘⏎, outlined) and the verb answer (⏎, filled: Run, Edit and run, Add and run, Delete, Edit, Create, Fetch, Allow). "Let this notebook run?" has Not now · **Run notebook** and no Always.
  - **Always this session** is Endeavor's own memory: it answers with the request's allow-once option and remembers a rule for the session, and later matching prompts are answered at once with no card (their row reads "allowed for this session"). Matching: the same file for edits and new files, the same site for fetches, for commands the prefix of Claude's own suggested rule ("don't ask again for `npm test` commands"; a command chained with `&&`, `;`, a pipe or a redirect never matches a prefix), else the exact command; other tools by the same tool. It answers only the prompt shown: prompts already waiting stay separate questions, answered one by one (each may be given Always too); only prompts that arrive after the rule exists are answered by it. On a run card it puts the session in Auto instead.
  - **In this folder**: on the agent's own prompts, when the agent keeps lasting rules in the session folder (Claude Code: `.claude/settings.local.json`) and the request has an allow-always option that writes one ("don't ask again for …"; not "allow all edits during this session", which changes the mode), Always this session gets a ⌄ with This session ⌘⏎ / In this folder. In this folder answers with the allow-always option; the agent writes the rule and Endeavor keeps no copy. This Mac's sessions only. Never on a card for a call the runtime holds (a run, or an edit in Manual): the agent's rule would answer only its own prompt, not the runtime.
  - **Several prompts**: the card shows the first, "1 of 3" at the heading's right, and under the card "◷ Then: Run a command on This Mac · Edit `plot_fit` and run it". Each is answered on its own; the count counts the batch, so it never goes back to "1 of 2". The card keeps the batch's tallest height (code shown in full doesn't count), so the chat above doesn't move.
  - **Keys** with the message box empty: ⏎ the filled answer, ⌘⏎ Always this session, Esc deny (a second Esc stops the turn; with the ⌄ menu open, Esc closes it first). Words in the box don't change the card: ⏎ queues them as while Claude works. Placeholder "Queue a message". Tab moves between the card's buttons and the Show all toggle. **In the notebook**, ⏎ answers the card too (the filled answer, as Run), but only while nothing in the page has the keyboard: after a click on the page's background, an output's text or a cell's margin. In a cell's editor, a field, or on a button or link, ⏎ stays the page's own (a new line in the cell), so typing in a cell while a card waits never answers it; click outside the cell first. Plain ⏎ only: ⇧⏎ and ⌘⏎ stay Pluto's, a held ⏎ repeating doesn't count, and Point's mode keeps it. The page names the card it saw, and ⏎ answers only that one: if it has gone or another took its place, nothing happens.
  - **Notebook**: the asked-about cells get the orange status bar and an orange line above them, "● Claude asks to run this."; cells that would re-run after them "Re-runs after it" in grey; cells it needs that never ran "Runs first: it hasn't run yet", also in grey. All go when the card is answered.
  - **Your run reaches a cell Claude asks to run**: Claude's edits land on the runtime's side, so Pluto doesn't count them as changed, and the user's own run re-runs whatever depends on what they changed. When ⌘S (Ctrl+S off macOS; the cells whose editor text differs), ⇧⏎ or ⌘⏎ in a cell, or Pluto's run button would reach a cell a waiting card asks to run (the cells run plus everything downstream, from Pluto's dependencies), the page stops it and asks in a small card at the bottom of the notebook (the dialog look, no backdrop): "**Claude is waiting for your answer on `b`.** Running your changes now also runs it." ("…on `b` and `c`. … also runs them."; "Running this now" for a cell's own run), with **Show `b`** ("Show them"; scrolls to the cells and outlines them while the card stays), Cancel (esc) and **Run anyway** (⏎, filled). Cancel: nothing runs and the edits stay unsubmitted. Run anyway does what the user did, through Pluto's own handlers, and once the asked-about cells are under way answers each card asking about them as its Run button does; the runtime then doesn't run them again (its result says they "already ran after the user's change"). Nothing is asked when no reached cell waits, nor in safe preview (⌘S there only saves).
  - **Ran another way**: if every cell a run card asks about (an `execute_cell` or `submit_changes` of cells Claude had already changed) has run while it waited, some way the page didn't catch, the card is answered as allowed with a note "b ran after your change", and the runtime doesn't run them again.
  - **Sidebar**: a session with a waiting prompt shows a filled orange bullet at the start of its row (see **Sidebar row marks**).
- **Sidebar row marks** (board GRows): every session row starts with a bullet in a fixed 12 px slot, so all titles start at the same x. The bullet shows the row's one mark, strongest first, or an idle ring when it has none. The dots are all 6 px across, so nothing jumps between states; the icon marks are drawn at 9 px, as small as they stay legible.

  | State | Bullet | Words (tooltip; VoiceOver reads them after the title) |
  |---|---|---|
  | Needs you | Filled orange dot (`accent`) | "Waiting for your answer" |
  | Stopped with an error | Red warning triangle (`danger`); the title keeps its colour | "Stopped with an error · open to try again" |
  | Claude is working | Filled grey dot (`text_muted`) whose opacity breathes 30 %–100 % and back over `motion_pulse`, eased in and out; steady and full with Reduce motion | "Claude is working" |
  | New reply | Orange ring, 6px, 1px stroke | "New reply" |
  | Its server isn't reachable | Wifi-off icon (`text_muted`) | "hoffman2 isn't reachable" |
  | Messages waiting to send | Clock icon (`text_muted`); the count is in the words | "2 messages wait to send once Claude is back" |
  | None (open or past session) | Hollow grey ring, 1 px (`text_faint`) | None |
  | Archived (past session, archived filter) | Archive icon (`text_section`), title in `text_section` | VoiceOver reads ", archived" |

  Needs you and new reply differ in shape (solid dot, hollow ring); new reply and idle differ by colour (orange ring, grey ring). Working differs from needs you by colour and the pulse; with Reduce motion only by colour, and the words say it. Working is what the composer's orbit shows: not while the turn waits for the network ("Waiting for the connection"), and not while a card waits, since needs you is stronger. Waiting is shown only while held because Claude can't be reached. A collapsed folder heading shows its rows' strongest mark after "›" ("Endeavor › ●"), next to the name rather than in the bullet column, where the folder name starts. When this Mac is offline, rows show no server or waiting marks (the status line says it). When they go: needs you when the question is answered; error when a new turn starts; working when the turn ends; new reply when the session is opened (it isn't set for the open session, nor for a turn the user stopped); server down and waiting by themselves once the server is back and the queue has sent.
- **Sidebar columns.** Measured from the sidebar's left edge (L) and right edge (R). Every sidebar row keeps a 2 px focus border and 10 px padding inside the sidebar's 6 px inset, so its content runs from L+18 to R−18.
  - **Left column, L+18 to L+30 (centre L+24):** the rows' bullets, "New session"'s +, the status line's mark and the search field's magnifier. The "Sessions" heading and folder names start at its left edge, L+18. Titles, "New session", "Show N more" and the status words start at L+38, after the 12 px slot and an 8 px gap.
  - **Right column, centre R−24:** 24 px buttons that reach 6 px into the row's end inset (R−36 to R−12): the rows' ⋮, the folders' +, the filter button, the search field's ×, and ⌘N (centred in at least 24 px; a wider Ctrl+N grows leftwards). The settings gear and the sidebar toggle centre on the same line. The search button sits just left of the filter button, centred at R−48.
  - The ⋮ always keeps its space, shown or not, so a title truncates with "…" at the same x on every row (R−44).
- **Sidebar spacing.** "Sessions" is 16 px below "New session" and sits right on top of the list: its first folder heading follows with no gap. Each later folder heading is 16 px below the folder before. So a heading is nearer what it heads than what's above it: about 26 px between the centres of "Sessions" and the first folder name, and of a folder name and its first row, against 44 px from "New session" to "Sessions" and 42 px from a folder's last row to the next folder name.
  - **In the background**: a prompt arriving while Endeavor isn't the active app sends one macOS notification, "Claude is waiting for you", with the question and the session's title; then none from any session for 10 minutes. No Dock badge. Clicking it brings Endeavor forward on that session. Only an app bundle can post them, so a bare development build logs the notification instead.
  - **Gone unanswered**: when the turn ends or Claude's process stops with a prompt waiting, the card goes and a note says "Claude stopped before you answered “Run rates?”"; a run still waiting in the runtime is denied. A card no call waits on any more stays up when the turn ends or Claude's process stops: the runtime keeps the answer for Claude's same call later (an older runtime doesn't say which cards those are, and its cards go as before). Allowing it while Claude is idle sends "Go ahead" for the user (once Claude is back, if its process stopped), and Claude makes the same call, which runs without asking again. When a message of the user's is already waiting, that message goes instead, and a note says "Allowed. Claude goes ahead when your next message is sent" (a queue paused after an error still waits on Send next). Stopping the turn denies it. When Claude gives up on a run the runtime holds (it cancels the call, or its connection closes), its card goes and a note says "Claude stopped waiting for your answer to “Run rates?”".
  - **Where run cards come from**: in Ask to run (and Manual), the runtime holds a call that runs code until the user answers its run card, whatever the agent. In Manual it also holds every call that changes the notebook (edit, add, delete, move or fold a cell, a new notebook), shown as the same edit card as the agent's own prompt ("Edit `rates`?" with the diff, "Nothing runs. In Manual, every change to the notebook asks."), so Manual asks before each change whatever the agent's own settings allow (Cursor's "Allow always", a personal Claude setup, a folder rule). Reads never wait. When the agent asks first itself about a call the runtime holds (Claude in Manual), its own prompt is let through at once, with no card and no mark on the row, so only the runtime's card asks. Always this session on a held edit answers later edits with the same tool at once ("allowed for this session"); on a run card it lets runs through without asking, and in Manual edits still ask. In Auto the runtime doesn't hold runs, so they ask nothing and their rows have no mark. With Julia that an older Endeavor started and the app can't use as it is (below), Manual falls back to the agent's own prompts.
  - **Denying a change in Manual**: it isn't made, even an edit that was to run after; the row reads "denied" and Claude is told the user chose not to make the change.
  - **Denying an edit that runs** in Ask to run ("Edit `b` and run it?", "Add `residuals` and run it?"): the edit is kept, staged and not run. Its row reads "denied" and still shows its diff, the end-of-turn card lists the cell, and the run-state note says it changed but hasn't run. Claude is told the user chose not to run it yet. No undo here; ⌘Z in the notebook brings the old code back.
- **Answers on the call's row** (board PAnswered): after a dot, in the row's faint grey: "allowed", "allowed for this session", "allowed in this folder", "ran without asking"; "denied" in red. An opened row that was asked about ends with the answer and its time, "Allowed at 14:02", "Denied at 14:06" (live answers only; replayed history has no times). A call with no row gets a note instead, "Allowed: edit a cell". A call a folder rule allowed never reaches Endeavor and has no mark.
- **Plan card** (plan mode): numbered steps; Keep planning · Start in Auto · **Start**. Once answered, the plan stays as a row, "Plan Bootstrap intervals for the decay rate · started" ("started in Auto", "kept planning"), which opens to the plan's call.
- **Allowed in this folder** (session menu, title ⌄, This Mac's sessions): the agent's rules for the folder, read from its settings file each time the list opens, in plain words ("Run commands starting with `npm test`", "Edit files in `data/`", "Fetch `juliastats.org`"), each with **Remove**, which deletes that entry from the file and leaves the rest of the file as written.
- **"You edited `x`"** lines record user actions in the notebook (the agent receives them too).
- **Reply** (boards: QQuote, QCompose, KPromptPlace): selecting text in a reply, or in a cell's code, output or rendered Markdown, shows a "Reply ⌘E" pill 6px under the selection's end (above it with no room below). ## Failure states

Boards XTurn, XStopped, XOpen. Three tiers. **Waiting** (Endeavor fixes it by itself): a muted line above the composer, no red or orange, at most Try now. **Failed** (it needs the user): one card where the thing would have been, with a title saying what didn't happen, a plain reason, what is kept, one primary button, and the raw error under Details, closed; a danger-coloured warning icon. **Recovered**: one quiet note in the transcript. The sidebar's status line holds app-wide states only (offline, signed out, Restarting Claude… with a spinner, Claude isn't running, Julia on <computer> stopped), with a red dot only when something needs the user.

- **A turn Claude couldn't answer** (servers busy, other server errors): "Claude couldn't answer", the reason ("Anthropic's servers are busy right now."), "Your message is kept.", **Try again** sends the same message again without a second bubble, and the card goes. No automatic retry. If Claude can't be reached at all, that's offline (waiting).
- **Usage limit**: waiting. "You've reached your Claude usage limit. It resets in 1 h 12 min, at 3:00 PM, and your message sends then." The time comes from Claude Code's message ("resets 3pm (America/Los_Angeles)", "resets Oct 3, 3:30pm (…)"); the line counts down by the minute, by the second in the last minute, and at zero the held message goes. Without a time: "It resets later", with Try now. The message shows "Not answered yet"; new ones queue.
- **A reply that stops partway** (the connection dropped mid-reply, the length limit, too many steps): what came stays; "Claude stopped before finishing" with the reason and **Continue**, which sends "Continue from where you stopped." as a new message. "You stopped Claude" stays a quiet note.
- **Claude's process stops**: it restarts by itself ("Claude stopped unexpectedly. Restarting it…", with a spinner); sessions load again where they were and messages queue meanwhile. Only a session whose reply was cut off gets "Claude restarted. This reply was cut off." with Continue. A second stop within a minute leaves it stopped: "Claude isn't running" above the composer of whichever session is open, with **Restart Claude**, Show logs (the app's log, in Finder) and Details (the error and the log's last lines).
- **A session opened before its Julia is up** (a past session clicked, or a first message sent, at launch): waiting. "Starting Julia…" with a spinner above the composer, then it opens, and a message sent meanwhile goes. A past session shows its summary meanwhile (see Layout, Opening a past session).
- **A session whose server can't be reached**: waiting. "Can't reach lab-server. Endeavor keeps trying." with a quiet **Try now** above the composer; the composer says "Write a message. It sends once lab-server is back."
- **A notebook file that's gone**: the pane says "Can't find fit_decay.jl", its path, "Nothing is there anymore. It may have been moved, renamed or deleted outside Endeavor.", with **Locate file…** and New notebook in this session. Locate file… works on every host: on This Mac the file panel, on a server Endeavor's folder browser (the new-session screen's), where a notebook is picked by clicking it. The new path is recorded for the session (it reopens there), a note says "The notebook is now …", and Claude is told with the next message.
- **Julia from another Endeavor**: Julia keeps running after the app quits (on a server, or with the setting on), so the app can reattach to one another Endeavor started. Each runtime says which build started it and the number for what its core offers (its interface). The app uses it as it is when that number is the app's own, or when this build started it, as EndeavorMCP's own clients do. Otherwise each session on that host gets a note: "Julia on lab-server was started by an older version of Endeavor. Restart Julia to use this one. Until then, some of Claude's notebook tools may not work as described." ("a newer version" when its number is higher.) Such a runtime still holds runs for the user's answer, so the app holds nothing back. One that says neither its build nor its interface may be from before the runtime held runs, so it runs no code in any mode: a call that would run code fails, with the agent told to have the user restart Julia, and its note says "Julia on lab-server was started by a version of Endeavor too old to ask before a run. Restart Julia to run code. Until then, Claude can read and edit the notebook but not run it." When Julia restarts on this version, a session that showed either note says "Julia on lab-server now runs this version of Endeavor. Ask to run asks before each run again."
- **Julia stops by itself**: the notebook pane says "Julia stopped unexpectedly": the file is saved, its outputs are gone until the cells run again, and, when known, which cell was running ("Very large data can run out of memory."). **Restart Julia**, Show log (This Mac's runtime log); the header chip says "Julia stopped". Restart reopens the notebook and runs it again; if Julia stops again during that run, the notebook opens in safe preview, and the callout says "Julia stopped again while running this notebook" and names the cell. A notebook's own Julia stopping is noticed whether or not its page is open and whether or not a cell was running, and a notebook tool call waiting on that run fails with the page's words ("Julia stopped unexpectedly while running `rates`. The notebook file is saved; its outputs are gone until the cells run again.").
- **A session that won't open**, in place of its transcript: open in the Claude Code CLI, "This session is open in Claude Code" with **Open a copy** and Try again (a message sent from the composer opens the copy first); otherwise "Couldn't open this session" with a plain reason when it can be told (history unreadable, folder gone, Claude not running), "The notebook is open beside it." when it is (it opened when its Julia was ready), "The notebook and its file are fine." when its file is there but not open, **Try again** and Details. A past session whose notebook only its history knows says "…, so Endeavor doesn't know its notebook yet." and adds **Open the notebook only**, which picks a notebook the way Locate file… does (file panel, or the server's folder browser from the session's folder), records it for the session and opens it beside the page.
- **One-off failures** (export, rename, move, run, restart, stop, new notebook, sign out): a notice under the control used, with its title ("Couldn't export fit_decay.html"), the reason, a way on (Export to…, Choose another name, Try again), Details and ×. It stays until closed or tried again. Run notebook (inside the page) and the pane's New notebook hang it at the top right of the pane; Sign out at the top of the window, over Settings.

## Open decisions

- Chat-panel radius: 8px scale (boards) vs Pluto's 4px everywhere.
- Undo for agent edits (per change / per cell) — explored, not in the final states. The runtime has no undo; it would restore the code from before the agent's edit, which the runtime keeps (`before`).
